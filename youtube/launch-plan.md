# YouTube Launch Plan

Goal: create a repeatable weekly video machine for Bench & Beacon, then publish the first strong public episode.

## Operating Defaults

- Channel role: public surface for Bench & Beacon live projects.
- First outcome: one private upload test, then one public flywheel episode.
- Cadence: Friday video, Tuesday and Thursday written derivatives.
- Length: 12 to 18 minutes for normal episodes, shorter only when the artifact demands it.
- Production level: polished enough to signal care, lean enough to repeat weekly.
- Gear rule: no new gear before video #1.
- Business rule: public proof and a smallest paid ask matter more than channel polish.

## Phase 0: Settle Blockers

- [ ] Confirm channel name and handle.
- [ ] Confirm canonical domain for on-screen credits: `kennyliu.io` or `kennypliu.com`.
- [ ] Confirm on-camera default: real face for hooks and bookends.
- [ ] Confirm first recording mode: clean lecture for pilot, live-capture for Ben B demos.
- [ ] Confirm first public episode title direction.
- [ ] Confirm the use-case collection prompt or paid ask that appears in the pilot.

Recommended defaults:

- Channel name: `Kenny Liu | Bench & Beacon` if the channel is personal-led.
- Pilot title direction: `The model was never the bottleneck`.
- Recording mode: clean iA Presenter or Keynote lecture with one short on-camera hook.

## Phase 1: Channel Foundation

- [ ] Open YouTube Studio and verify the channel already exists.
- [ ] Confirm phone verification and feature eligibility.
- [ ] Set handle.
- [ ] Set default audience to not made for kids, if appropriate.
- [ ] Upload avatar using the Bench & Beacon telescope-wrench mark.
- [ ] Upload banner at 2560x1440 with all text inside the safe center area.
- [ ] Add About copy.
- [ ] Add canonical links.
- [ ] Set upload defaults: category, language, description footer, tags, visibility default.
- [ ] Create initial playlists:
  - Bench & Beacon live projects.
  - Personalized AI stack.
  - Voice and walk method.
  - Weekly briefing automation.
  - Ben B demos.

## Phase 2: Setup Tax

- [ ] Build deck master in iA Presenter or Keynote.
- [ ] Build thumbnail master at 1280x720, plus a higher-resolution working file if useful.
- [ ] Build lower-third template.
- [ ] Build title card and chapter divider.
- [ ] Build end screen plate.
- [ ] Create reusable description, chapter, pinned comment, and source block templates.
- [ ] Create episode folder template.
- [ ] Confirm capture tools for:
  - on-camera video;
  - screen recording;
  - slide recording;
  - clean audio;
  - captions.
- [ ] Create one export preset: H.264 MP4, 1080p or 4K depending on workflow friction.

## Phase 3: Private Upload Test

Use a 60-second private test before the public pilot.

- [ ] Record 10 seconds on-camera.
- [ ] Record 20 seconds of deck narration.
- [ ] Record 20 seconds of screen/demo capture.
- [ ] Export the video.
- [ ] Generate or upload captions.
- [ ] Create one test thumbnail.
- [ ] Upload private.
- [ ] Check playback on desktop and phone.
- [ ] Check audio level, caption timing, chapters, thumbnail crop, and description rendering.
- [ ] Note any fixes directly in this folder or in the private ops repo.

## Phase 4: First Public Episode

Episode: `The model was never the bottleneck`.

- [ ] Package first: title, thumbnail claim, viewer promise.
- [ ] Write a one-page brief, not a full script.
- [ ] Script only the first 10 to 20 seconds.
- [ ] Build the deck around the artifact, not around process narration.
- [ ] Record on-camera hook.
- [ ] Record deck narration.
- [ ] Capture any system/demo footage.
- [ ] Edit lean: trim, captions, chapters, lower third, light color/audio polish.
- [ ] Export and upload private first.
- [ ] Add end screen and cards.
- [ ] Publish or schedule.
- [ ] Pin CTA comment.
- [ ] Derive Tuesday and Thursday posts from the same transcript.
- [ ] Log any concrete buyer/use-case signals that come back from the episode.

## Phase 5: Cadence

- [ ] Record the Ben B demo test run.
- [ ] Choose the next 4 videos from `content-slate.md`.
- [ ] Build a 3-video buffer if weekly cadence starts slipping.
- [ ] Track only three metrics at first:
  - click-through rate;
  - average view duration;
  - first-minute retention.
- [ ] Review after 3 to 4 videos, not after one video.

## Definition Of Done

The project is ready to move from setup into cadence when:

- the channel has basic public identity;
- the visual package is reusable;
- one private upload test has passed;
- one public episode is live;
- the next episode has a package, outline, and recording slot.
